# 将军席—阵营区 关系编辑器（设计规格 · 实现提示词）

> 适用项目：xiangqi-service-mode ／ 自定义地图（2.0）前置功能
> 用法：可直接作为任务提示词交给 Codex，也可作为设计参考文档。
> 版本：v0.1（2026-10-11 讨论稿）

---

## 0. 目标

地图编辑器里，「将军席」与「阵营区」存在**多对多**绑定：一个将军席可管辖多个阵营区，一个阵营区也可归属多个将军席，关系允许交叉与重叠。两类区域在棋盘上坐标分散，需要一套「棋盘牵动式勾选 + 关系梳理窗口」的双向联动编辑体验，且**PC 与移动端共用一套指针操作**。

---

## 1. 术语

- **将军席**（General Seat，记 `G1 / G2 …`）：较小的核心区域，**不可重叠**。
- **阵营区**（Faction Zone，记 `Z1 / Z2 …`）：较大的区域，**可以互相重叠**。
- **关系**：将军席 ↔ 阵营区 的一条绑定，可带属性（权重 / 优先级 / 备注）。
- 一个坐标点可能同时属于多个对象（含将军席 × 阵营区、阵营区 × 阵营区），点击可能命中多个。

---

## 2. 数据模型

1. 不用单向映射。用**关系三元组数组**：`{ generalId, zoneId, weight?, note? }`。
2. 由它派生两个索引：`byGeneral`、`byZone`，供渲染与查询。
3. 校验规则：
   - 孤儿检查：某阵营区无任何将军席绑定 → 警告（不阻断）
   - 悬空引用：引用了不存在的 id → 报错
   - 重复关系去重：同一 G+Z 视为一条
4. 数据挂在 `core/map.mjs` 的 map 描述里（与 `zones` 并列新增 `relations`），**不写进规则内核**。

---

## 3. 区域视觉基线

- 正常情况下，**将军席与阵营区的边框都是白色**；只有被选中/被牵动时才变色。
- **将军席的识别方式**：其内部所覆盖的格子添加一层**半透明白色底**（沿用现有表现手法）。
- 阵营区：以大范围边框圈定，不遮挡内部棋盘。
- 视觉分层原则：将军席用「底 + 边框」，阵营区用「边框 + 可选极淡填充」，靠**材质**而非颜色区分两者，避免重叠时互相遮盖。

---

## 4. 棋盘侧交互：牵动式勾选

**取消悬停方案，一律以点击为准。**

### 4.1 命中优先级

点击某坐标时，按以下顺序决定选中对象：

1. **将军席优先**（将军席通常较小、被阵营区包住；重叠处一律先命中将军席）
2. 否则命中**阵营区**（若该点落在多个重叠阵营区内，则**全部选中**，见第 5 节包边方案）
3. 若该点未规划为任何区域 → **无任何动作**

### 4.2 牵动规则

- 选中**将军席** → 其绑定的所有阵营区同时高亮，并在梳理窗口中对应显示。
- 选中**阵营区** → 其绑定的所有将军席同时高亮，并在梳理窗口中对应显示。
- 主/关联用**两种亮度**区分：被直接点中的为「主体色」，被牵动出的为「关联色」，无关对象变暗。

### 4.3 自动归类与优先级（分阶段）

- **第 0 层 · 几何默认（自动围圈）**：绘制阶段优先级最高。规则：阵营区几何上**围住**某将军席 → 自动建立绑定。此阶段关系由几何唯一决定（区域尚未画好，无从手动选择）。
- **第 1 层 · 手动补丁（显式增删）**：区域画好后，用户的手动绑定/解绑作为覆盖补丁，记为「显式添加 / 显式排除」。
- **最终关系 = 几何默认 ∪ 显式添加 − 显式排除**。
- **重算时机**：对象新建 / 删除 / 移动 / 改形时重算几何默认层，保留手动补丁。
- **补丁失效**：一条「显式排除」仅在其 (G,Z) 仍处于几何包含关系时有效；不再包含时自动作废清理。

---

## 5. 重叠与「无限包边」方案

背景：阵营区之间可多层重叠，重叠数量不可预知，无法为每个成员分配唯一固定颜色；且棋盘可缩放，**文字/序号在棋盘上会随缩小而互相重叠**，故棋盘包边一律不放文字。

### 5.1 编码通道：颜色 × 线型（主方案）

- 基础色 7 种：红、橙、黄、绿、蓝、靛、紫。
- 7 色用尽后以**组合扩展**：单色 7 + 双色 21 + 三色 35 + … 直到全组合，共 **2^7 − 1 = 127 种**（7 色的所有非空子集）。该数与阵营区数量上限 127 **一一对应**（见 §9）。
- ⚠️ 但**纯混色在 3 色以上会发灰、彼此难分辨**，因此叠加第二通道——**线型 / 分段**：实线、虚线、点线、波浪线（可再加线宽与流动方向）。
  - 颜色 7 × 线型 4 = **28 种高清晰度组合**，且互不干扰
- 推荐实现：组合色用**分段渐变边**呈现（一条边交替出现各成员色段），而非物理混色——每个成员的颜色段依然可辨。

### 5.2 文字锚点只放在梳理窗口

- 棋盘包边**只承载颜色 / 线型**，不放编号或名称（缩放会重叠）。
- 编号、名称、色块一律显示在**梳理窗口**条目上（窗口不缩放，永远清晰），棋盘 ↔ 窗口靠颜色/线型一一对应。

### 5.3 动态流动

- 重叠区外轮廓使用**流动描边**（CSS 渐变 + 动画），同一重叠簇共享流动边，用**流动方向 / 相位**进一步区分成员。

命中阵营区重叠部分时：涉及的阵营区**全部亮起**，各自显示对应颜色/线型的流动包边，并牵动各自的将军席。

## 6. 配置关系的两种方式

### 6.1 方式一：棋盘两段式配对

1. **第一次点击**：选中一个将军席或一个阵营区（该侧可多选，例如重叠处弹窗多选）。
2. **第二次点击**：选中另一侧对象。
3. 若两侧**类型交叉**（一侧是将军席集合、另一侧是阵营区集合）→ 执行**两两绑定**（笛卡尔积）。
4. 若两侧同类型（都是将军席或都是阵营区）→ 无效，提示并重置。
5. **解绑**：若所选配对集合**已全部绑定**，则重复同样两步操作改为**全部解除**；否则补齐绑定。（即"全有则解、否则建"）

### 6.2 方式二：梳理窗口配对

1. **点交叉点**：直接 toggle 该条关系（已绑定→解除，未绑定→建立）。
2. **行列表头配对**：先点一个「将军席行头」，再点一个「阵营区列头」（顺序可互换），自动定位其交叉点并 toggle。
3. 重复操作同一交叉点 = 取消配对。

---

## 7. 梳理窗口（矩阵）

1. 行 = 将军席，列 = 阵营区；交叉格 `●` = 存在绑定，可显示权重。
2. 行列顺序默认与棋盘地理顺序一致（左→右、上→下），支持拖拽重排。
3. **动态刷新**：
   - 随绑定结果变化实时刷新；
   - 随地图上**新增/删除**将军席、阵营区而**动态增删行列**。
4. 点行/列头 → 该行/列所有 `●` 高亮，同时棋盘关联对象高亮（双色：主体 / 关联）。
5. 点单个格 → 仅高亮这一条关系。
6. 与棋盘**双向联动**：窗口点选 → 棋盘高亮；棋盘点选 → 窗口行列高亮。
7. 重叠阵营区在窗口条目上显示与棋盘包边一致的**颜色 + 线型**，并附带编号/名称等文字锚点。

---

## 8. 交互规范（PC 与移动端统一 · 纯指针操作）

1. 只用鼠标与触摸的**公共交集**：单击、长按、拖拽。
2. 映射：
   - **单击** = 选中；再点同一对象 = 取消
   - **长按（触摸）/ 右键（鼠标）** = 上下文菜单 / 重叠命中列表
   - **拖拽** = 平移画布；位移超过约 `6px` 判定为拖拽，否则算点击
   - **滚轮（PC）/ 双指捏合（移动）** = 缩放；另提供 `+ / −` 按钮兜底
3. **核心功能不得依赖 hover**；hover 仅作 PC 端预览增强。
4. 点击目标 `≥ 44×44px`；缩放后徽章与矩阵格仍需可点。
5. 响应式：宽屏显示完整矩阵（表头冻结、可横向滚动）；窄屏自动切换为「抽屉式」——选中一个将军席后展开其绑定的阵营区列表。

---

## 9. 技术约束

- 遵守现有分层：`core/` 不感知 DOM；渲染与交互只在 `web/` 层；地图描述走 `core/map.mjs`。
- 数据驱动，禁止写死具体坐标或编号。
- 与现有 1.0 功能兼容，不破坏经典 9×10 地图。
- **阵营区数量上限 127**：达到上限时禁止新增并友好提示，与配色组合数一一对应。
- 性能提示：127 对绘制不是红线，真正的开销在**重叠命中检测**与**关系矩阵**；命中检测用空间索引（如网格分桶），矩阵用稀疏存储（只存实际存在的边）。

---

## 10. 范围外（本次不做）

- 不改动现有棋子规则与胜负逻辑。
- 不涉及海战 / 空战 / 多国战争等扩展。
- 不做服务端持久化，先本地状态。

## 11. 验收标准

- 能增删改一条关系，矩阵与棋盘实时同步。
- 点表头能按行列点亮关联对象，主体 / 关联双色可区分。
- 棋盘点击遵循「将军席优先」，点空白区域无动作。
- 阵营区重叠时全部亮起并显示不同颜色/线型的流动彩边，梳理窗口同色同步（文字锚点仅在窗口侧）。
- 两段式配对可建立与解除绑定；"全有则解、否则建"逻辑正确。
- 自动归类：绘制阶段围住将军席的阵营区自动绑定（几何默认层）；手动增删为覆盖补丁，最终关系 = 几何 ∪ 显式添加 − 显式排除；显式排除在几何关系失效后自动清理。
- 鼠标与触摸（模拟）下核心操作均可用，无 hover 依赖。
- 孤儿与悬空引用能被校验提示。

## 实现状态（xiangqi-service-mode）

- 核心关系模型位于 core/relations.mjs，提供稀疏三元组、派生索引、几何默认、显式补丁、空间命中索引及 127 区域上限。
- 地图描述位于 core/map.mjs，经典 9×10 地图保留空关系字段以兼容 1.0。
- Web 编辑器位于 web/relations-editor.mjs，提供将军席优先命中、重叠阵营区集合命中、两段式配对、矩阵单格和表头联动。
- 当前页面使用本地自定义地图样例验证交互，后续可替换为自定义地图加载器。
