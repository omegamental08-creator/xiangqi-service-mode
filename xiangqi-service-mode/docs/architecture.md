# 象棋兵役模式程序架构

## 当前目标

先建立可演进的 1.0 双人本地对战骨架。网页端和 Windows 桌面端加载同一套规则内核，不复制棋子规则。

## 分层

- `core/`: 纯 JavaScript 规则内核。输入状态和行动，输出新状态；不能依赖 DOM、Electron 或 HTTP。
- `web/`: 展示层和交互层，只调用内核公开 API。
- `electron-main.mjs`: 桌面壳，只负责窗口和加载共享网页入口。
- `core/map.mjs`: 地图描述接口。经典 9x10 棋盘不是规则内核的硬编码终点，未来自定义地图通过地图对象接入。
- `core/contracts.mjs`: 行动封装、存档格式和扩展契约。
- `core/extensions.mjs`: 扩展注册表，为海战、空战、寄生棋子、多国战争预留。

## 核心边界

核心内核拥有：基础地形、基础棋子、回合、步数、主动攻击次数、生产区/淘汰区、基础胜负。

扩展只能通过注册契约提供：扩展状态、额外行动、行动结算。扩展不应直接绕过核心结算；若未来某个完整模式需要替代胜负或回合制，应声明新的模式适配器，而不是偷偷修改 1.0。

## 版本策略

- `1.0`: 经典棋盘、纯陆战、双人本地对战。
- `2.0`: 自定义地图、海战和水性单位。
- `3.0`: 空战和防空体系。
- `4.0`: 多国战争、威胁递归、结盟与狂热残局。

存档带有 `formatVersion`、`rulesVersion` 和 `mode`，升级时通过迁移器处理，不直接假设所有存档都是最新结构。

## 下一步实现顺序

1. 将当前 1.0 规则中的歧义写成决策表并冻结。
2. 完善核心行动模型和自动测试。
3. 补齐网页的保存、读取、悔棋、回放。
4. 打包 Electron/Tauri 桌面版本。
5. 在不破坏 1.0 的前提下逐个接入扩展模块。
