# 任务：实现「将军席—阵营区」关系编辑器（自定义地图 2.0 前置）

> 可直接作为任务提示词交给 Codex。
> 配套设计说明见 `docs/relations-editor-spec.md`。

## 背景
xiangqi-service-mode 即将支持自定义地图。地图中的「将军席」与「阵营区」存在**多对多**绑定：一个将军席可管辖多个阵营区，一个阵营区也可归属多个将军席，关系允许交叉与重叠。两类区域在棋盘上坐标分散，难以对应。需要实现一套「棋盘牵动式勾选 + 关系梳理窗口」的双向联动编辑体验，PC 与移动端共用一套指针操作。

## 术语
- **将军席**（General Seat，记 `G1 / G2 …`）：较小的核心区域，**不可重叠**。
- **阵营区**（Faction Zone，记 `Z1 / Z2 …`）：较大的区域，**可以互相重叠**，数量上限 **127**。
- **关系**：将军席 ↔ 阵营区 的一条绑定，可带属性（权重 / 优先级 / 备注）。
- 同一坐标可能同时属于多个对象，点击可能命中多个。

---

## 1. 数据模型
1. 用**关系三元组数组**：`{ generalId, zoneId, weight?, note? }`，不要用单向映射。
2. 派生两个索引：`byGeneral`、`byZone`，供渲染与查询。
3. **稀疏存储**：只保存实际存在的关系。
4. 校验规则：
   - 孤儿检查：阵营区无任何绑定 → 警告（不阻断）
   - 悬空引用：引用了不存在的 id → 报错
   - 重复关系去重：同一 G+Z 视为一条
5. 数据挂在 `core/map.mjs` 的 map 描述中（与 `zones` 并列新增 `relations`），**不写入规则内核**。

## 2. 区域视觉基线
- 正常状态：将军席与阵营区边框**均为白色**，仅被选中/被牵动时才变色。
- **将军席识别方式**：其覆盖的格子上叠加一层**半透明白色底**（沿用现有表现）。
- 阵营区：大范围边框圈定，可用极淡填充，不遮挡内部棋盘。
- 分层原则：将军席用「底 + 边框」，阵营区用「边框（+极淡填充）」，靠**材质**而非颜色区分，避免重叠时互相遮盖。

## 3. 棋盘侧交互：牵动式勾选
### 3.1 命中优先级（一律点击，不用悬停）
1. **将军席优先**（重叠处先命中将军席）。
2. 否则命中**阵营区**；若该点处于多个重叠阵营区内，则**全部选中**。
3. 未规划区域 → **无任何动作**。

### 3.2 牵动规则
- 选中**将军席** → 其绑定的阵营区全部高亮，并在梳理窗口对应显示。
- 选中**阵营区** → 其绑定的将军席全部高亮，并在梳理窗口对应显示。
- 双色区分：直接点中的为「主体色」，牵动出的为「关联色」，无关对象变暗。

### 3.3 自动归类与优先级（分阶段，非单一优先级）
- **第 0 层 · 几何默认（自动围圈）**：绘制阶段优先级最高。规则：阵营区几何上**围住**某将军席 → 自动建立绑定。此阶段关系由几何唯一决定（区域还没画好，无从手动选择）。
- **第 1 层 · 手动补丁（显式增删）**：区域画好后，用户的手动绑定/解绑作为覆盖补丁，记录为「显式添加 / 显式排除」。
- **最终关系 = 几何默认 ∪ 显式添加 − 显式排除**。
- **重算时机**：任一将军席/阵营区被新建、删除、移动或改形时，重算几何默认层，并保留手动补丁。
- **补丁失效**：一条「显式排除」仅在其 (G,Z) 仍处于几何包含关系时有效；二者几何上不再包含时，该排除项自动作废清理（防幽灵排除）。

## 4. 重叠与「无限包边」
### 4.1 编码：颜色 × 线型
- 基础色 7 种：红、橙、黄、绿、蓝、靛、紫。
- 用尽后以**组合扩展**：单色 7 + 双色 21 + 三色 35 + …，共 `2^7 − 1 = 127` 种，与阵营区上限 127 **一一对应**。
- 因纯混色在 3 色以上会发灰难辨，叠加第二通道**线型 / 分段**：实线、虚线、点线、波浪线（可再加线宽、流动方向）。
- 组合色用**分段渐变边**呈现（一条边交替出现各成员色段），**不要物理混色**。

### 4.2 文字锚点只在梳理窗口
- 棋盘包边**只承载颜色 / 线型，不放编号或名称**（棋盘可缩放，文字会重叠）。
- 编号、名称、色块显示在**梳理窗口**条目上（窗口不缩放，永远清晰）。

### 4.3 动态流动
- 重叠区外轮廓使用**流动描边**（CSS 渐变 + 动画），同一重叠簇共享流动边，用**流动方向 / 相位**区分成员。

命中阵营区重叠部分时：涉及阵营区**全部亮起**，各显示对应颜色/线型的流动包边，并牵动各自将军席。

## 5. 配置关系的两种方式
### 5.1 棋盘两段式配对
1. 第一次点击：选中一个将军席或阵营区（该侧可多选）。
2. 第二次点击：选中另一侧对象。
3. 若两侧类型交叉（一侧将军席集合、一侧阵营区集合）→ **两两绑定**（笛卡尔积）。
4. 若两侧同类型 → 无效并重置提示。
5. 解绑：若所选配对集合**已全部绑定**，则重复操作改为**全部解除**；否则补齐绑定（**全有则解，否则建**）。

### 5.2 梳理窗口配对
1. 点交叉点：toggle 该条关系。
2. 行列表头配对：先点「将军席行头」，再点「阵营区列头」（顺序可互换），自动定位交叉点并 toggle。
3. 重复操作同一交叉点 = 取消配对。

## 6. 梳理窗口（矩阵）
1. 行 = 将军席，列 = 阵营区；交叉格 `●` = 存在绑定，可显示权重。
2. 行列顺序默认与棋盘地理顺序一致（左→右、上→下），支持拖拽重排。
3. **动态刷新**：随绑定结果实时刷新；随地图新增/删除将军席、阵营区**动态增删行列**。
4. 点行/列头 → 该行/列所有 `●` 高亮，同时棋盘关联对象高亮（主体/关联双色）。
5. 点单个格 → 仅高亮这一条关系。
6. **双向联动**：窗口点选 → 棋盘高亮；棋盘点选 → 窗口行列高亮。
7. 重叠阵营区在窗口条目上显示与棋盘包边一致的颜色/线型 + 编号/名称。

## 7. 交互规范（PC 与移动端统一，纯指针、不依赖键盘）
1. 只用公共交集：**单击、长按、拖拽**。
2. 映射：
   - **单击** = 选中；再点同一对象 = 取消
   - **长按（触摸）/ 右键（鼠标）** = 上下文菜单 / 重叠命中列表
   - **拖拽** = 平移画布（位移 > 约 `6px` 判定为拖拽，否则算点击）
   - **滚轮（PC）/ 双指捏合（移动）** = 缩放；提供 `+/−` 按钮兜底
3. 核心功能**不得依赖 hover**；hover 仅作 PC 端预览增强。
4. 点击目标 `≥ 44×44px`；缩放后徽章与矩阵格仍可点。
5. 响应式：宽屏显示完整矩阵（表头冻结、可横向滚动）；窄屏切换为「抽屉式」（选中将军席后展开其绑定阵营区列表）。

## 8. 技术约束
- 遵守现有分层：`core/` 不感知 DOM；渲染与交互只在 `web/` 层；地图描述走 `core/map.mjs`。
- 数据驱动，禁止写死坐标或编号。
- 与现有 1.0 兼容，不破坏经典 9×10 地图。
- **阵营区数量上限 127**：超出时禁止新增并友好提示。
- 性能：命中检测用空间索引（网格分桶）；矩阵用稀疏存储。

## 9. 范围外（本次不做）
- 不改动现有棋子规则与胜负逻辑。
- 不涉及海战/空战/多国战争等扩展。
- 不做服务端持久化，先本地状态。

## 10. 验收标准
- 能增删改一条关系，矩阵与棋盘实时同步。
- 点表头能按行列点亮关联对象，主体/关联双色可区分。
- 棋盘点击遵循「将军席优先」，点空白无动作。
- 阵营区重叠时全部亮起并显示不同颜色/线型的流动彩边，梳理窗口同色同步（文字锚点仅在窗口）。
- 两段式配对可建立与解除绑定；「全有则解、否则建」逻辑正确。
- 自动归类：绘制阶段围住将军席的阵营区自动绑定（几何默认层）；手动增删为覆盖补丁，最终关系 = 几何 ∪ 显式添加 − 显式排除；显式排除在几何关系失效后自动清理。
- 鼠标与触摸（模拟）下核心操作均可用，无 hover 依赖。
- 孤儿与悬空引用能被校验提示。
- 阵营区数量达 127 时禁止继续新增。
